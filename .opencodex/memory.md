# Prisma (бывш. AnalyzPRO) — устойчивые факты

## Проект (Prisma — Telegram-бот для анализа мед. анализов, Go; ранее назывался AnalyzPRO)
- **РЕБРЕНДИНГ (актуально):** публичное название проекта — **Prisma** (старое `AnalyzPRO` полностью выведено из пользовательских текстов). Кроме того, из всех текстов, видимых пользователю (меню, сообщения, отчёты, веб-аппы, шаблоны), **удалены упоминания ИИ/AI/нейросети** — бот позиционируется как «аналитический помощник Prisma», а не ИИ-сервис (например, «Быстрая консультация (с ИИ)» → «Быстрая консультация», «искусственный интеллект» → «сервис Prisma»). ⚠️ При правке бренда/текстов меняй ТОЛЬКО пользовательские строки; Go-импорты и системные пути (`github.com/theamornoir/analyzpro`, `bin/analyzpro`, `/tmp/analyzpro.lock`, `./data/analyzpro.db`) НЕ трогай — это внутренние артефакты, не видимые пользователю. Версия Mini App после правки статики — `WebAppAssetsVersion = "v8"`.
- Локальное тестирование Mini App на телефоне: `make mini` поднимает бота + HTTPS-туннель и прокидывает `WEBAPP_URL=<туннель>/dashboard`. **Menu Button (кнопка слева в чате бота) НЕ открывает дашборд напрямую** — `SetupMenuButton` в `bot.go` сбрасывает её в дефолт (`MenuButtonDefault`, список команд). Сводка здоровья открывается ТОЛЬКО из клавиатуры бота: «📊 Здоровье» → хаб → inline-кнопка «Открыть» в `router.handleDashboard` (URL версионируется `?v=<WebAppAssetsVersion>`). Сброс делается при каждом старте (на случай старых запусков, где кнопка была Mini App).
- **Остановка из ЛЮБОГО терминала:** `make mini-stop` — убивает запущенный `make mini` по lock-PID (`/tmp/analyzpro-mini.lock/pid`), туннель (ngrok/cloudflared), бота, освобождает `:8080` и снимает lock. Реализовано через `scripts/mini-stop.sh` (Makefile-цель `mini-stop`). Это решает проблему «Ctrl+C не работает, потому что `make mini` крутится в чужом/невидимом терминале».
- Туннель по умолчанию — ngrok (бесплатный план = лимит **1 агент** → `err_ngrok_3200`). Повторяющаяся проблема: пользователь запускал `make mini` в нескольких терминалах → два ngrok-агента → ошибка.
- `scripts/run-miniapp.sh` теперь:
  - (1) **singleton через `mkdir`-lock (`/tmp/analyzpro-mini.lock`) с PID-файлом** (`$LOCKDIR/pid`). Второй `make mini` не стартует, а пишет «уже запущен» и выходит. Lock **PID-зависимый** — если терминал убит/закрыт и владелец мёртв, lock считается устаревшим и `make mini` его снимает и стартует сам.
  - (2) опция `TUNNEL=cloudflared make mini` — быстрый туннель Cloudflare без лимита агентов.
  - (3) `LOG` через `LOG="/tmp/analyzpro-tunnel-$$.log"` (PID-суффикс) — без `mktemp`-шаблона, который на macOS трактуется буквально.
  - cleanup (trap EXIT/INT/TERM) удаляет pid-файл и lock-каталог.
- `flock` на macOS НЕТ — синглтон через атомарный `mkdir` + PID-проверка.
- Экран Telegram «you are about to visit <domain>» — НЕ ошибка, штатное подтверждение перед любым Mini App; нажимать «Открыть».

## Сводка здоровья (Mini App, /dashboard)
- Дашборд `/dashboard` (handler `internal/bot/handlers/dashboard`) читает историю из SQL-repo мониторинга (`monitoring_history`, `monitoring_sqlrepo.New(dbConn)`); данные переживают перезапуск. Файлы Mini App: `internal/bot/handlers/dashboard/webapp_files/{index.html,app.js,style.css}` (go:embed).
- **Премиум-гейт дашборда:** `GET /api/metrics` НЕ возвращает 403 — при валидном initData всегда отдаёт 200 + поле `premiumRequired`. «Богатые» метрики скрыты (обнулены) для не-Premium; `noData` виден ВСЕМ.
- **Онбординг доступен ВСЕМ:** дашборд открывается через inline-кнопку «Открыть» в `router.handleDashboard` (клавиатура бота → «📊 Здоровье» → хаб). Этот путь проходит премиум-проверку, но для не-Premium всё равно открывает приложение с карточкой регистрации; при `noData` фронтенд показывает `#registerCard` (имя/возраст/пол/рост/вес/цель) независимо от Premium. Upsell (`premium_required`) — только при `premiumRequired && !noData`.
- **Регистрация профиля:** `POST /api/profile` сохраняет профиль как `HistoryEntry{Type:"questionnaire"}` в `monitoring_history` (без Premium-гейта). После сохранения `noData=false` и сводка перерисовывается. Бэкенд проверен: тест `TestSaveProfileSeedsDashboard` (профиль → `NoData=false`, подтягивается имя/возраст/рекомендации).
- ⚠️ `payment.MockPaymentService` НЕ синхронизирует `isPremium` из Telegram: пользователь считается Premium только при записи в `./data/premium_users.json`.
- **КОРЕНЬ «пустой Сводки здоровья / нет формы регистрации» (актуально):** первопричина была НЕ в кэше и не в бэкенде, а в том, что `<script src="...chart.js CDN">` стоял в `<head>` **БЕЗ `defer/async`** и БЛОКИРОВАЛ парсинг страницы. Если CDN недоступен/медленный на телефоне → `app.js` (в конце `<body>`) никогда не выполнялся, а `#registerCard` имел `display:none` по умолчанию → пользователь видел пустой статический «скелет» без формы. **Исправлено:** (1) `chart.js` и `app.js` грузятся с `defer` (chart.js до app.js); (2) `#registerCard` видим по умолчанию (без `display:none`) — форма появляется даже если app.js не выполнился; (3) `drawTrend` защищён от отсутствующего `Chart` (`typeof Chart === 'undefined'` → return). Сервер при этом корректен: у пользователя без истории `buildMetrics` возвращает `noData:true`.
- **КОРЕНЬ «форма видна, но кнопка «Сохранить профиль» ничего не делает» (актуально):** обработчик кнопки навешивался ТОЛЬКО внутри `showRegisterCard()` (вызывается из `render()` при `noData`). Поскольку форма видима по умолчанию, при сбое `render()` (ошибка загрузки метрик, частично закэшированный старый `app.js`) форма показывалась, но кнопка оставалась без обработчика. **Исправлено:** обработчик `submitProfile` навешивается ОДИН раз при загрузке скрипта — IIFE `bindSaveButton` в конце `app.js` (`btn.addEventListener('click', submitProfile)`); из `showRegisterCard` привязка убрана (чтобы не дублировать → двойной POST). Плюс в `submitProfile` добавлен статус «Сохранение…», блокировка повторного нажатия и чёткие ошибки в `#regError`/сообщении.
- **КОРЕНЬ «нажимаю сохранить → пишет «не удалось получить данные сессии Telegram»» (актуально, v7):** после v5/v6 (`tgWebAppData`-fallback из query) пользователь всё ещё получал пустой `initData`. **Две причины + фиксы:**
  - (1) `bot.go` редиректил `/dashboard`→`/dashboard/` через **`301 Moved Permanently`** — WebView **кэширует** 301, и при повторном открытии Mini App Telegram мог подставить `tgWebAppData` из устаревшего редиректа (или он терялся) → `initData` пуст. **Исправлено:** редиректы `/dashboard` и `/monitoring` теперь **`307 Temporary Redirect`** (не кэшируется), параметры запуска не теряются между открытиями.
  - (2) `getInitData()` читал `tgWebAppData` только из **query**, хотя на ряде платформ Telegram кладёт его в **hash**. **Исправлено:** `getInitData()` (v7) читает `initData` из трёх источников — `window.Telegram.WebApp.initData` → `tgWebAppData` из query → `tgWebAppData` из hash; плюс **перечитывает заново на каждом вызове** (на сабмите `window.Telegram.WebApp` уже «проснулся») и кэширует первое успешное значение. В `DOMContentLoaded` сразу захватываем `initData`, когда Telegram готов.
  - Сообщение об ошибке стало понятнее: «откройте через кнопку бота внутри Telegram, а не в обычном браузере».
- **Telegram WebView агрессивно кэширует статики Mini App.** В `dashboard.ServeWebApp` стоит `Cache-Control: no-store` + отрезание `?v=` в пути. WebApp-URL (inline-кнопки «Открыть» в `router.handleDashboard`/`handleMonitoring`) версионируется `?v=<WebAppAssetsVersion>` через `router.WithWebAppVersion`, а ссылки на активы в `webapp_files/index.html` — `app.js?v=<ver>`/`style.css?v=<ver>`. (Menu Button дашборд не открывает — см. выше.)
- **Правило при правке фронта Mini App:** при изменении `webapp_files/{index.html,app.js,style.css}` ОБЯЗАТЕЛЬНО увеличить `router.WebAppAssetsVersion` (`"v3"` → … → `"v7"` …). Сейчас актуально **`"v7"`**. Иначе Telegram отдаст закэшированную старую версию. Признак кэша: curl на туннеле — свежая версия, а в Telegram на телефоне — старая. Не делай `<script>` в `<head>` без `defer`, иначе блокировка CDN снова «убьёт» загрузку `app.js`. ⚠️ Не привязывай интерактивные обработчики (кнопки форм) только внутри render/onShow — навешивай их при загрузке скрипта. `getInitData()` должен читать `initData` из `window.Telegram.WebApp.initData`, из `tgWebAppData` в query **И** из `tgWebAppData` в hash, и **перечитывать на каждом вызове** (не только в момент загрузки) — иначе пустой initData ломает сохранение профиля. ⚠️ Редиректы на `/dashboard`/`/monitoring` — только `307`, НЕ `301` (301 кэшируется WebView и роняет `tgWebAppData` между открытиями).

## AI-прокси (гео-блок Gemini во Франции и т.п.)
- `internal/ai/httpclient/client.go` — единый AI-HTTP-клиент (`AIHTTPClient`) для Gemini/DeepSeek/Claude/YandexGPT. Прокси-совместимый: `transport.Proxy = proxyResolver`.
- **Приоритет прокси** (в `proxyResolver`/`resolveExplicitProxy`): `config.GeminiProxy` (из `.env` `GEMINI_PROXY`) → env `GEMINI_PROXY`/`AI_HTTP_PROXY` → системный `http.ProxyFromEnvironment` (HTTP_PROXY/HTTPS_PROXY/NO_PROXY) → прямое соединение.
- `init()` строит клиент ДО `config.Load()` (читает env-фоллбэк). После загрузки конфига `internal/app/app.go` вызывает `httpclient.Configure(cfg.GeminiProxy)` — он перестраивает клиент, если `GEMINI_PROXY` задан в `.env`.
- Поддерживаемые схемы явного прокси: `http`/`https` (через CONNECT, `http.ProxyURL`) и `socks5` (через кастомный `dialThroughSOCKS5` — stdlib не умеет socks5-схему в `ProxyURL`). При ошибке SOCKS5 — фоллбэк на прямое соединение с логом.
- **Логи (сразу видно, работает ли прокси):** `✅ Gemini client using proxy: <url>` (для явного — схема+хост, userinfo скрыт `***`; для системного — пометка `(system HTTP_PROXY/HTTPS_PROXY)`) и `⚠️ Gemini client using DIRECT connection (no proxy)`.
- `.env`: `GEMINI_PROXY=socks5://127.0.0.1:1080` (локальный SOCKS5-порт VPN/Clash). Прокси затрагивает ТОЛЬКО AI-вызовы, не Telegram-трафик. ⚠️ Если порт не слушает (VPN выключен) — клиент логирует `SOCKS5 proxy ... failed ... connection refused, falling back to direct` и идёт напрямую (сейчас именно это: VPN выключен, Gemini недоступен/гео-блок + модели 404 для новых ключей).
- Важно: если VPN — системный (tun), прямое соединение Go уже пойдёт через него и прокси не нужен; при proxy-стиле VPN (Clash/Proxifier) задай `GEMINI_PROXY`.
- **Gemini-модель и авто-фоллбэк (актуально):** `.env` пользователя содержит `GOOGLE_AI_MODEL=gemini-2.5-flash`, который Google теперь отдаёт **404 "This model ... is no longer available to new users"** (новые ключи). `.env` править нельзя (секреты/блок), поэтому сделан **авто-фоллбэк по цепочке моделей** в `internal/ai/gemini/gemini_http.go`: `doRequest` перебирает `candidateModels()` = [сконфигурированная] + [`gemini-2.5-flash-latest`, `gemini-2.5-flash-002`, `gemini-2.5-flash-001`, `gemini-2.0-flash`, `gemini-2.5-pro-latest`, `gemini-2.5-pro`]; при ошибке «модель не найдена/недоступна» (404 или 400 с сообщением о модели; детектор `isModelNotFoundError`) переключается на следующую. Логи: `🔄 Gemini: модель ... недоступна — переключаюсь на фоллбэк ...` и `✅ Gemini: фоллбэк-модель ... сработала`. Дефолтные модели унифицированы на `gemini-2.5-flash-latest` в трёх местах: `config.go` (`getEnv("GOOGLE_AI_MODEL", ...)`), `gemini.go` (`NewGeminiClient`), `orchestrator/gemini.go` (`NewGeminiProvider`).
- **Реальный HTTP-статус ошибки НЕ маскируется:** раньше `doRequest` превращал любую ошибку `FetchWithRetry` в `503`+пустое тело, скрывая настоящую причину (например, 404 модели показывался как «503»). Теперь `FetchWithRetry` (`internal/ai/httpclient/client.go`) возвращает `HTTPError{StatusCode, Message}` с реальным кодом и телом, `doRequest` пропагирует их наверх; `FetchWithRetry` повторяет только 5xx/429 (4xx — сразу, без бесполезных повторов).

## Провайдер OpenRouter (основной free-путь, text+фото+PDF)
- Добавлен `internal/ai/orchestrator/openrouter.go` — провайдер через **OpenRouter** (OpenAI-совместимый API, без гео-блоков). Это **первый (основной) провайдер** в `NewOrchestrator()` (перед YandexGPT/Gemini/DeepSeek/Claude).
- Реализует весь `AIProvider`-интерфейс: текст (`GenerateAnalysisSummary`/`JSON`), фото (vision, `data:image/...;base64` в content-part), **PDF** и bioscan.
- **PDF-обработка:** OpenAI-совместимые эндпоинты (вкл. OpenRouter) НЕ принимают PDF-файлы напрямую, поэтому PDF извлекается в текст pure-Go библиотекой `github.com/ledongthuc/pdf` (`extractPDFText` → `pdf.NewReader` + `GetPlainText()`) и шлётся как обычный текст. Сканированные PDF (только картинки) → ошибка «PDF не содержит извлекаемого текста». `go mod tidy` резолвит `ledongthuc/pdf` в версию `v0.0.0-20220302134840-0c2507a12d80` (та же API: `NewReader(io.ReaderAt, int64)` + `GetPlainText() (io.Reader, error)`).
- **Модели и фоллбэк (АКТУАЛЬНО — сверено с GET https://openrouter.ai/api/v1/models, prompt=0, modality=image):** старые `:free`-модели (llama-3.2-11b-vision-instruct:free, qwen2.5-vl-72b-instruct:free, gemini-2.5-flash:free, llama-3.1-8b-instruct:free) OpenRouter **удалил из бесплатного тарифа** → 404 «unavailable for free». Живые бесплатные vision-модели (текст+изображение, PDF шлётся как текст): дефолт `google/gemma-4-26b-a4b-it:free`; цепочка `openRouterFallbackModels` (в КОДЕ — источник истины) = [nvidia/nemotron-nano-12b-v2-vl:free, google/gemma-4-31b-it:free, nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free, openrouter/free]. При недоступности/лимите (404/429/400-model/5xx) — **авто-фоллбэк**; детектор `isOpenRouterFallbackError` (тип `*openai.Error`, по StatusCode+Message). Логи: `🌐 OpenRouter model: %s`, `🔄 OpenRouter: пробуем модель %s`, `⚠️ OpenRouter: модель %s недоступна — %v`.
- ⚠️ **ТАЙМАУТ ТОЖЕ ТРИГГЕРИТ ФОЛЛБЭК (добавлено):** раньше при «висении» бесплатной модели срабатывал `Client.Timeout` транспорта (45с) и openai-go возвращал ошибку НЕ типа `*openai.Error` (это контекст/сетевая ошибка) → `isOpenRouterFallbackError` возвращал `false` → **весь провайдер OpenRouter валился**, и бот уходил к мёртвым Yandex/Gemini/DeepSeek/Claude. Теперь `isOpenRouterFallbackError` ловит `context.DeadlineExceeded`/`context.Canceled` и `net.Error.Timeout()`, и `complete()` даёт каждой модели свой `context.WithTimeout(ctx, openRouterModelTimeout=40s)` — поэтому при таймауте одной модели провайдер уходит на СЛЕДУЮЩУЮ из цепочки (фоллбэк получает свежий лимит времени, т.к. общий `ctx` не просрочен).
- ⚠️ **OpenRouter free = shared upstream pool rate-limit (АКТУАЛЬНО, живая ситуация пользователя):** бесплатные модели разделяют общий пул лимитов провайдера → частые **429** («temporarily rate-limited upstream. Please retry shortly, or add your own key to accumulate your rate limits») и даже **таймауты** (free-pool «висит»). При 429 провайдер уходит на следующую модель (разные вендоры Google/NVIDIA — разные пулы, шанс пробиться выше). Если ВСЕ free-модели ушли в 429/таймаут — надёжное решение: добавить свой ключ провайдера как **BYOK** в OpenRouter (Settings → Integrations) или платную модель. В `.env` пользователя сейчас `OPENROUTER_MODEL=google/gemma-4-26b-a4b-it:free` (ЖИВАЯ модель) — код с ней работает, при 429/таймауте уходит на остальные живые `:free`. Цепочка фоллбэков в коде живая и срабатывает.
- `.env.example` = `google/gemma-4-26b-a4b-it:free`.
- **HTTP-клиент:** `option.WithHTTPClient(httpclient.AIHTTPClient)` — тот же прокси-совместимый клиент, что и у остальных AI-провайдеров (GEMINI_PROXY/системный/direct). Плюс заголовки `HTTP-Referer`/`X-Title` (рекомендация OpenRouter).
- **Ключ:** `OPENROUTER_API_KEY` в `.env`/`.env.example`; если пуст — провайдер не регистрируется (`NewOpenRouterProvider` → nil).
- ⚠️ **Правка `openrouter.go` капризна:** строки с составным UTF-8 (em-dash `—`, стрелка `→`) могут не совпасть при `replace_text` (exact-match fail), а `read_file` иногда отдаёт ЗАКЭШИРОВАННУЮ старую версию (в одной сессии правка `import` применилась, а остальное — нет, хотя скрипт упал ДО записи — проверяйте реальный диск через `grep`/`sed`). При правке этого файла ВСЕГДА: (1) читайте реальное состояние через `grep`/`sed` в терминале, а не доверяйте `read_file`; (2) делайте замены через Python с побайтовой сверкой (`assert old in s`) и подстроковыми якорями без привязки к табуляции; (3) после правок — `gofmt -w` (файл может оказаться не отформатированным, `gofmt -l` его покажет).

## Прочие AI-провайдеры (фоллбэки оркестратора)
- **DeepSeek НЕ умеет vision (важно):** используемая модель `deepseek-chat` отдаёт **400 `unknown variant image_url, expected text`** на фото — т.е. vision НЕ поддерживается, несмотря на комментарий «поддерживает мультимодальный (vision) анализ» в `deepseek.go` (комментарий неверен). Значит DeepSeek бесполезен для анализа файлов/фото (в file-пути всегда падает: image → 400, PDF не умеет вообще). Годится только для текстового/JSON-анализа (`GenerateAnalysisSummary`/`GenerateAnalysisJSON`). Для фото-запроса оркестратор тратит на DeepSeek один быстрый проваленный вызов перед Claude.
- **YandexGPT:** падает с `400 invalid model_uri` (модель `yandexgpt`, URI `gpt://<folderID>/yandexgpt`) — конфиг-проблема папки/доступа к модели (вне кода; пользователь во Франции).
