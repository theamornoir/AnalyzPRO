Menu Button НЕ открывает дашборд (сброс в `bot.go`); Мой профиль открывается ТОЛЬКО из клавиатуры «📊 Здоровье» → хаб → «Открыть». ## Онбординг (слайдер) + команда сброса (актуально)
- 8 шагов онбординга (подробный слайдер: база/анализы/Bioscan basic → Premium/Bioscan PRO/Мой профиль/Мониторинг/Консультация/Сервис; inline-кнопки «➡️ Дальше», на 8-м — «📝 Соглашение») → текст соглашения (v1.0, `internal/locales/agreement.go`) → inline «✅ Принять».
- Статус: `models.User.OnboardingCompleted bool` (JSON `onboarding_completed`); интерфейс `UserRepository.UpdateUserOnboardingStatus`; реализован в mock/file/sql репозиториях; хелперы `storage.SetOnboardingCompleted` / `IsOnboardingCompleted`.
- Поток: `menu.StartHandler` — новый (OnboardingCompleted=false) → `onboarding.SendStep(ctx,b,chatID,1)`; существующий уже-согласный (agreed && !onboarded) → помечается пройденным и сразу в меню (миграция, чтобы не гонять старых юзеров); пройденный → главное меню.
- Шаги/соглашение = отдельные сообщения; `router.handleOnboarding` при переходе делает `helpers.DeleteMessage` предыдущего (чтобы не плодить историю). Callback'и: `onboarding_step_2..N` (N = len(Steps) в `onboarding.go`), `onboarding_agreement`, `onboarding_accept` (финал ставит `agreementStorage.SetAgreed` + `SetOnboardingCompleted(true)` + главное меню). Файлы: `internal/bot/handlers/onboarding/onboarding.go`, `internal/locales/onboarding.go`.
- Команда сброса (только ADMIN_CHAT_ID): `/resetme` и `/reset_premium` → `menu.ResetHandler`: `payment.ResetPremium`, `SetOnboardingCompleted(false)`, `agreementStorage.Reset` (сброс соглашения, чтобы онбординг проходился заново), `stateManager.Reset`. Текст: `locales.MsgResetDone`. Зарегистрировано в `bot.go`.
- ТЕСТИРОВАНИЕ ОНБОРДИНГА: разработчик — уже согласившийся пользователь, поэтому `/start` по логике миграции сразу даёт главное меню (онбординг не показывается). Чтобы увидеть слайдер: набрать `/resetme` (ответ «Статус Premium и онбординг сброшены…») и затем `/start`. Без `/resetme` онбординг не появится.

## Мой профиль (Mini App, /dashboard)
- Дашборд `/dashboard` (`internal/bot/handlers/dashboard`) читает `monitoring_history` (данные переживают рестарт). Файлы: `internal/bot/handlers/dashboard/webapp_files/{index.html,app.js,style.css}` (go:embed). `Cache-Control: no-store` + отрезание `?v=`. WebApp-URL открывается с `?v=<WebAppAssetsVersion>` (версия в query), а сами активы грузятся по ВЕРСИОНИРОВАННОМУ ПУТИ: `index.html` ссылается на `style.<ver>.css`/`app.<ver>.js`, а `ServeWebApp` (dashboard.go) резолвит любую версию в актуальный встроенный файл. Telegram WebView кэширует JS/CSS по пути и игнорирует query, поэтому версия В ПУТИ - единственный надёжный сброс кэша. Редиректы `/dashboard`/`/monitoring` — только `307`.
- Премиум-гейт: `GET /api/metrics` всегда 200 + `premiumRequired`; богатые метрики скрыты для не-Premium, `noData` виден всем. Онбординг всем: профиль `POST /api/profile` (Type `questionnaire`) снимает `noData`. ⚠️ `MockPaymentService` НЕ синхронизирует Premium из Telegram — только запись в `./data/premium_users.json`.
- `getInitData()` (v7) читает initData из `window.Telegram.WebApp.initData` → `tgWebAppData` query → `tgWebAppData` hash, перечитывает на каждом вызове. `chart.js`/`app.js` грузятся с `defer`; `#registerCard` видим по умолчанию; `submitProfile` навешивается один раз при загрузке скрипта.
- **Блок «Динамика» (вкладка «Обзор»):** линейный график индекса здоровья по времени. Рисуется ТОЛЬКО при 2+ замерах (`app.js`: `trendChart` показывается при `trend.values.length >= 2`); при 1 замере график НЕ рисуется и плашка в «Обзоре» НЕ показывается (только текущий индекс + шкала). Плашка-подсказка «Пока один отчёт (ДД.ММ). Загрузите следующий анализ, чтобы увидеть сравнение и динамику.» ПЕРЕНЕСЕНА в раздел «Анализы»: элемент `#analysisTrendPlaceholder` в карточке `analysisReportCard`, управляется в `renderReportGroup()` (показывается при `visible.length <= 1`, скрывается при 2+). Тренд и индекс здоровья в бэкенде (`dashboard.go buildMetrics`) считаются ТОЛЬКО по реальным замерам (`type="analysis"`/`type="bioscan"`); заполненная анкета-профиль (`type="questionnaire"`) исключена, чтобы не «раздувать» число точек и не прятать подсказку.
  - **Radar-график в карточке отчёта (`analysisChartWrap`/`chartAnalysis` для анализа, `bioscanChartWrap`/`chartBioscan` для Bioscan):** рисуется по `latest.scores` ТОЛЬКО при `visible.length >= 2` (visible = отчёты, видимые с учётом премиум-гейта). При 1 отчёте график принудительно СКРЫТ и уничтожен (`chart.destroy()`), чтобы под плашкой «Пока один отчёт» не висел срез показателей. Так пользователь при одном анализе видит только плашку, без графика.

## Аналитика (PostHog, актуально)
- Библиотека: `github.com/posthog/posthog-go` (в go.mod, direct). Ключ проекта — `POSTHOG_API_KEY` (env, уже в .env). Если ключ пустой — `posthog.New("")` возвращает no-op клиент, события тихо игнорируются (бот не падает).
- Клиент: `internal/analytics/posthog.go` — структура `AnalyticsClient{ client posthog.Client }` + `NewAnalyticsClient(apiKey)`, методы `Track(userID int64, event string, properties map[string]interface{}) error` и `Close() error`. Рядом — глобальный клиент: `InitPostHog(apiKey)`, пакетный `Track(...)` (тот же сигнатур, но без error — тихо логирует) и `ClosePostHog()`. Глобальный доступ выбран вместо DI-проброса через все хендлеры (разрешено ТЗ), чтобы не трогать десятки конструкторов.
- Инициализация: `internal/app/app.go` → `analytics.InitPostHog(cfg.PostHogAPIKey)` (рядом с `analytics.Init`), закрытие — `defer analytics.ClosePostHog()` в `App.Run`.
- События (DistinctId = telegram chatID). **Имя события в PostHog = человекочитаемая РУССКАЯ подпись** (см. `internal/analytics/labels.go`, карта `semanticEventLabels` и `interactionLabel`), а не технический ключ - чтобы в дашборде сразу было видно понятный текст. Технические ключи сохранены как свойство `action`/`source` для фильтрации. Предметные события: `Запустил бота` (бывш. `user_started`, menu/start.go), `Анализ обработан` (бывш. `analysis_processed`, upload/upload_report.go; свойство `analysis_type` = `extended`/`regular` через `isExtendedAnalysis`), `Bioscan завершён` (бывш. `bioscan_completed`, bioscan/bioscan_process.go), `Открыл Premium` (бывш. `premium_view`, menu/premium.go), `Купил Premium` (бывш. `premium_purchased`, menu/premium_callback.go HandlePremiumConfirm; свойства `tariff`, `changed`), `Открыл Мой профиль` (бывш. `dashboard_opened`, dashboard/dashboard.go `Metrics` после валидации initData; НЕ в демо-режиме).
- Проверка: запуск бота, прохождение флоу → вкладка Activity в app.posthog.com. Старый JSONL-аналитик (`internal/analytics/analytics.go`, `EmitEvent`) сохранён и работает параллельно.
- **Полный clickstream (каждое нажатие):** функция `TrackInteraction(userID, source, action, props)` (в `posthog.go`) шлёт событие на КАЖДОЕ взаимодействие. Подключена в `router.handle` на самом входе: для `update.CallbackQuery` -> `source="callback"`, `action=callback_data`; для `update.Message` -> `source="command"` (если текст начинается с `/`) или `"message"`, `action=текст`, плюс свойство `media` (`text`/`photo`/`document`/`voice`/`video`). **Имя события = русская подпись**, раскрываемая из `callback_data`/текста кнопки/команды функцией `interactionLabel` (карты `years`...): напр. `section_analysis` -> `Открыл раздел Анализы`, `upload_process` -> `Нажал Обработать анализы`, `section_health_summary` -> `Открыл Мой профиль`, динамические `premium_*`/`premium_confirm_*`/`onboarding_step_*` раскрываются в `Выбрал тариф Premium` / `Подтвердил оплату accrual` / `Онбординг: шаг N`. Свободный текст без кнопки -> `Свободное сообщение` (сам текст в `action`); команда -> `Команда /start`. Дополняет предметные события и даёт в дашборде видимость буквально каждого клика/команды/сообщения.

## Система напоминаний / уведомлений (добавлено 2026-08-19)
- Ненавязчивые уведомления пользователям, чтобы не забывали о боте. Пакет `internal/bot/reminders/reminder.go`:
  • `RunReminderLoop(ctx, b *tgbot.Bot, store *storage.Storage, monitorRepo monitoring.Repository)` — фоновый цикл (goroutine в `app.Run`), раз в 6ч проверяет всех пользователей по `users.last_activity_date`. Для любого неактивного ≥10 дней (и ≥30 дней без данных) шлёт СЛУЧАЙНОЕ короткое уведомление из пула `locales.Reminders` через `locales.GetRandomReminder()` (15 сообщений, 3 категории: напоминание о данных / призыв к действию / мотивация; каждое ≤200 символов). После отправки ставит `last_activity_date=now` (дебаунс → периодичность ~10–14 дней, не чаще). Уважает `Preferences.NotificationsEnabled` (отказ = пропуск). Пул и `GetRandomReminder()` — в `internal/locales/reminders.go` (старые длинные `MsgReminder`/`MsgMotivational` удалены). `SendTestNotification` (тест по кнопке в «Сервис») тоже шлёт `GetRandomReminder()` для kind `reminder`/`motivation`.
  • `RunReminderLoop(ctx, b *tgbot.Bot, store *storage.Storage, monitorRepo monitoring.Repository)` — фоновый цикл (goroutine в `app.Run`), раз в 6ч проверяет всех пользователей по `users.last_activity_date`. >30 дней неактивности → `locales.MsgReminder` (напоминание о повторном анализе); 14–30 дней и есть сохранённые данные (`monitorRepo.ListHistory`) → `locales.MsgMotivational`. После отправки ставит `last_activity_date=now` (дебаунс, чтобы не спамить). Уважает `Preferences.NotificationsEnabled` (отказ = пропуск).
  • `BroadcastFeature(ctx, b, store, text)` — одноразовая рассылка анонса (напр. новой фичи) всем, кто не отключил уведомления.
